# swaps — domain spec
v1.4 · owned by pm-swaps. The business rules of this domain, each testable, each naming the story it serves. v1.3 applied DESIGN-REVIEW-3; v1.4 applies DESIGN-REVIEW-4.

## Rules
| Rule | Statement | Serves | Testable as |
|---|---|---|---|
| R-swaps-01 | Only the holder requests a swap of an assignment, on a published week, while now < the deadline (24 hours before the shift's start instant, by the injected clock) | US-swaps-001 | not_holder, week_draft, past_deadline (reads scheduling, IR-01) |
| R-swaps-02 | One open request per assignment | US-swaps-001 | request_open |
| R-swaps-03 | Only the named counterpart answers, by one answer operation with an outcome, only while the request is open in state requested; an answer sets answered_at and, on decline, answer_reason (required on declined, absent on accepted) | US-swaps-002 | not_counterpart, wrong_state, past_deadline |
| R-swaps-04 | Only an open accepted request is decided, by one decide operation with an outcome (approve or refuse); approval is one action in one transaction: transfer through scheduling first (IR-02, commits nothing itself), then one Decision row (approved) and the request mirrors it; a refused transfer records a Decision refused with the transfer's reason and the decider who attempted it, and the operation succeeds — an error reason is reserved for calls that changed nothing; a refusal records a Decision refused with the reason code; atomicity rests on the one-transaction-per-request rule of the architecture | US-swaps-003 | wrong_state, past_deadline; the Decision row and the mirrored state |
| R-swaps-05 | Nobody decides a swap they are party to; any admin or planner who is not a party decides; the pending list marks requests the viewer is party to | US-swaps-003, US-swaps-005 | party_to_swap; the party mark |
| R-swaps-06 | A request is open when its stored state is requested or accepted and now < its deadline; a request in those states at or after the deadline is shown expired — derived on read, never stored, never notified — and is not pending, carries no badge and shows no controls; swaps answers IR-07 from this rule and R-swaps-01/02: pending per assignment, and requestable = holder's own row, published week, no open request, now < deadline | US-swaps-004, US-swaps-005, US-scheduling-004 | the expired display state; absence from pending; no badge; requestable |
| R-swaps-07 | Reason codes are enumerated and required: request sick, family, travel, other; decline unavailable, other; refusal fairness, coverage, policy, other — Decision.reason is absent on approved and on refused is one of those four from the caller or counterpart_overlap / counterpart_inactive set only by the system; a caller who sends a system code, or any reason with outcome approve, gets invalid_reason | US-swaps-001, US-swaps-002, US-swaps-003 | reason_required, invalid_reason; the enum |
| R-swaps-08 | The counterpart is a member other than the requester, active, who holds no slot on that shift — checked in that order | US-swaps-001 | counterpart_self, counterpart_inactive, counterpart_on_shift (reads scheduling IR-01, identity IR-09) |
| R-swaps-09 | Lists are ordered by a stored timestamp with id as the tiebreak: a member's requests newest first by created_at then id descending; pending decisions oldest first by answered_at then id ascending; a listed request carries its shift's date and start, both parties' names, its answer_reason and its Decision | US-swaps-004, US-swaps-005 | the order and the embedded fields |

## Interfaces this domain needs from others
- scheduling: read an assignment — its holder, its shift (id, date, start instant, end, current holder ids) and its week's state (IR-01, also for the lists of US-swaps-004/005); transfer an assignment to the counterpart inside the caller's transaction, refused on overlap or inactivity (IR-02)
- notifications: emit swap_requested / swap_accepted / swap_declined / swap_approved / swap_refused with self-contained payloads (IR-03)
- identity: whether the counterpart is active; the eligible deciders; member names for the payloads and the lists (IR-09)
