## M1 Foundations · closed 2026-11-07 · tag m1-foundations
1. What did the units of this milestone get wrong, and what found it? The layering scan (`tests/layering_scan.py`, guarded by ADU-00) printed `→` and `—`, and on a cp1252 pipe its child process died with `UnicodeEncodeError`. Every M1 ✅ had been written from a gate the session ran in a shell with `PYTHONUTF8=1`, so no M1 test had ever run in the operator's default console. It was found by the operator's first own gate at the M1 release: `2 failed, 40 passed, 1 warning in 19.79s`. → became FB-01: a defect session; four permanent tests appended to `tests/test_layering.py` under Q-06's grant; ADU-00 gains an arm (ADU-PLAN v1.2). Upstream it is the plugin's FB-18, fixed in the adapter (f6b0143).
2. What nearly slipped through? (a) The first gate ran in Crucible's venv, `C:\dev\crucible-data\.venv`, the User-level `UV_PROJECT_ENVIRONMENT`, and changed it (uv uninstalled 14 packages and installed 19). A red result on the wrong interpreter would have been triaged as this project's. It was caught only because the release session read the interpreter path in the output. → became the interpreter line at the head of the operator's gate (`sys.prefix`, the locale encoding, `utf8_mode`), first used at this close; upstream, the plugin's FB-20 (open). The User-level variable is still set; it is on the operator's machine, outside this project. (b) The workspace database `rota.sqlite` is not covered by `.gitignore`'s hard-rule-3 block, and the default workspace `.rota` sits wherever the server starts. The release session found it while rehearsing the use-it run; no test did. → became FB-02, deferred to ADU-11 as O-01. (c) The plan's M1 row said "every operation answers 501 not_built", but a caller without a token gets 401 (ADU-02's arm, ADU-PLAN.md:129). → became ADU-PLAN v1.2, with the row corrected. (d) No one had compared the contract's JSON twin to the YAML since D-11. At this close they are equal both as data and byte for byte (js-yaml 5.5.0 from the npx cache), but no test compares them, by design, since there is no YAML parser in the roster. → became nothing in the documents: D-11 makes regeneration the architect's step at every contract change, and the comparison command is in this close's journal block for the next.
3. One change to the method, if any. The environment of a gate run is part of its result. Neither of M1's two surprises could be seen in a bare "N passed": FB-01 was hidden by `PYTHONUTF8=1`, and the gate ran in Crucible's venv. So a gate the operator is asked to run, at a release or a closure, starts by printing the interpreter, the encoding and the UTF-8 mode, and the result is recorded with them. → became plugin feedback for the operator to carry upstream (the release skill's step 2 and the closure hand-over). In this repository it is the practice of this close; `adu.toml` is protected and unchanged.
